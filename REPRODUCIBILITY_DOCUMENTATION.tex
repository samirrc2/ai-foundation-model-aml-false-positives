\section{Purpose and scope}

This document describes the supporting data-and-code archive that accompanies the manuscript (the reproducibility capsule under \code{capsule/}). The archive is a self-contained, offline, deterministic reproduction: from a single command it regenerates every reported number, table, and figure and verifies each result by re-running the analysis and comparing byte for byte. No network access, no API keys, and no paid model calls are required. The permanent citable version is the Code Ocean capsule at \url{https://doi.org/10.24433/CO.4804007.v1} (MIT licence); the same tree is mirrored in the project repository.

The study uses only \emph{synthetic} transaction data. A strict wall separates two phases: an offline \emph{analysis} that reproduces every claim from frozen inputs (documented here), and a live \emph{capture} phase that originally queried commercial model APIs and is retained for transparency only (Section~8). Because commercial models change over time, the capture is deliberately not part of the reproducible core; the frozen model-response corpus it produced is shipped and hash-verified.

\section{Quick start}

\begin{verbatim}
cd capsule
pip install -r code/requirements.txt
bash reproduce.sh
\end{verbatim}

Or, for a byte-identical run in the pinned container:

\begin{verbatim}
cd capsule/environment
docker build -t repro . && docker run --rm repro
\end{verbatim}

On Code Ocean, press \textbf{Reproducible Run} (which executes \code{code/run}).

\textbf{Expected result:} the integrity check passes, the full analysis regenerates the committed outputs, the second independent run is byte-identical (SHA-256 of every result file matches), and the run prints \code{\#\# REPRODUCIBLE} and exits~0. Total runtime is well under a minute on a standard laptop.

The primary panel is the frozen response corpus in \code{data/capture/}. Each per-case screening decision is reduced from its valid (non-ERROR) replicate calls by the pre-registered modal-vote rule (decision~D4): on legitimate cases a 2--2 tie is not counted as a false positive (strict majority required); on suspicious cases a 2--2 tie is counted as caught.

\subsection{Provenance and integrity}
\code{data/frozen/*.freeze.json} records the SHA-256 of each of the ten capture CSVs, and \code{data/manifest/battery\_manifest.json} records the content hash and case counts of the battery. \code{docs/} holds the frozen pre-registration and its amendment and pivot, so any silent change to an input or to the design is detected before the analysis runs (Section~7). \code{docs/data\_collection.md} documents how the corpus was captured; \code{docs/model\_manifest.md} and \code{docs/probe\_receipts.json} record the served-model identifiers.

\subsection{Data sources}
All analysis inputs are synthetic and self-contained: the battery is generated deterministically (seed \code{20260715}) from typologies anchored to the FATF catalogue and to established synthetic-AML data structures (SAML-D; the AMLSim lineage). No external, proprietary, or personal data are used or distributed, and no download is required to reproduce any result. The original capture queried the OpenAI and Google model APIs; those responses are frozen in \code{data/capture/} and are the only trace of the live phase the reproduction consumes.

\code{schema.py} defines the constrained-JSON screening schema; \code{io\_paths.py} resolves input/output locations. The modules under \code{code/capture/} (Section~8) are not part of the reproduction.

\subsection{Pipeline order}
\code{reproduce.sh} runs the modules in dependency order. All outputs are timestamp-free, so re-runs are byte-identical:

\begin{verbatim}
verify_data (battery hash + capture freeze receipts)
  -> altrisk -> baselines -> alertvolume -> classification
  -> table1/table2 + metrics_summary
  -> replication_check (byte-identical re-run)
\end{verbatim}

\section{Reproduction and verification}

\code{reproduce.sh} performs the following stages and exits non-zero if any fails:

\begin{enumerate}\setlength{\itemsep}{2pt}
\item \textbf{Integrity.} Regenerates the 600-case battery from seed \code{20260715} and confirms its SHA-256 matches \code{data/manifest/battery\_manifest.json}; confirms each of the ten capture CSVs matches its \code{data/frozen/*.freeze.json} receipt. (The freeze step that produced those receipts refuses any capture file with an ERROR rate above 2\%; the observed rate is 0.08\%, i.e.\ 10 of 12{,}120 rows.)
\item \textbf{Regeneration.} Runs the full analysis (Section~5.2) from the frozen inputs only.
\item \textbf{Byte-identical re-run.} \code{replication\_check.py} re-runs the whole analysis in a second, isolated output directory and confirms the SHA-256 of every result file is identical.
\end{enumerate}

\textbf{Determinism.} Analysis seed \code{4242}; the cluster bootstrap uses 2{,}000 fixed-seed resamples over the eight typology strata, so its intervals are exactly reproducible. The reproduction makes no network calls.

\textbf{Environment.} The pinned analysis environment is \code{numpy==2.2.6}, \code{scikit-learn==1.7.2}, \code{scipy==1.18.0}, \code{pyyaml==6.0.3}, and \code{pydantic==2.13.4} (with \code{pytest==8.3.5} for the optional test suite), on Python~3.12. Exact pins are in \code{code/requirements.txt}; \code{environment/Dockerfile} builds the same environment for a byte-identical run on any machine. The figures are shipped as static artifacts and are excluded from the byte-identical check; regenerating them is optional and needs \code{matplotlib}, which is not part of the pinned analysis dependencies.

\section{Live data collection (not part of the reproduction)}

\code{code/capture/} documents how the model-response corpus was originally collected: \code{orchestrator.py} drives the capture grid; \code{agent.py} issues the constrained-JSON screening calls; \code{probe.py} pins the served-model identifier; \code{ledger.py} and \code{check\_limits.py} enforce a hard spend cap; \code{freeze.py} writes the SHA-256 freeze receipts; \code{secrets.py} loads API keys. This phase requires internet access, OpenAI and Google API keys, and incurs cost, and is intentionally excluded from the reproducible core: all reported results derive only from the frozen captures in \code{data/capture/}.
