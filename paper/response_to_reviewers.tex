\concern{Editor, Concern \#1}

\concern{Editor comment:}

\rvcomment{``Please address the label-dependent aggregation rule by reporting primary results under a label-independent rule and providing sensitivity analyses under alternative tie policies. Also discuss the limitations of case construct validity and statistical independence assumptions.''}

\rvcomment{-Shiping Wang}

\textbf{Author response:}

\begin{itemize}

\item We agree, and the correction is larger than a change of rule. Decision~D4 as preregistered is already label-independent: the decisions log and both preregistration documents specify the modal replicate decision with ties broken toward \texttt{flag}, with no reference to the case label. The implemented benign branch required a strict majority, which is an undisclosed deviation. The label-independent rule requested here is therefore the preregistered rule, and we have restored it rather than adopted a new one.

\item Under the preregistered rule the false-positive rates are 2.3, 7.7, 37.0, 44.0 and 85.7 percent, a spread of 83.3 pp (95\% CI 71.8--93.7) against 82.7 pp as submitted. The spread is 77.7 to 85.3 pp across five aggregation rules and four single-call configurations, with no reversal of model order in any of the nine.

\item On construct validity, no independent AML expert adjudication or inter-rater check was performed; labels reflect the generator-defined case templates. On statistical independence, cluster-bootstrap intervals quantify uncertainty across the eight case-template strata, and a cluster-level permutation procedure tests the global null: none of 2,000 permuted statistics reached the observed value (Monte Carlo $p \approx 0.0005$), alongside the corrected case-level Cochran's $Q = 585.0$ ($p \approx 2.7\times10^{-125}$).

\end{itemize}

\textbf{Author action:}

\begin{itemize}

\item Section 2.3 was rewritten to state decision~D4 as preregistered, to report the deviation in the benign branch, and to make the preregistered label-independent rule primary.

\item Section 2.3 now records the departure and its effect on every affected number.

\item The Appendix~A sentence attributing a label-dependent rule to preregistration was corrected; D4 does not condition on the case label.

\item New Table 1 reports false-positive rates, the spread and Cochran's $Q$ under five aggregation rules and four single-call configurations.

\item Section 4.2 gained two limitation paragraphs, one on label construct validity and one on the independence assumptions of the primary tests.

\item Table 1 retains the deviating rule alongside the preregistered rule so that both sets of numbers remain in the record.

\end{itemize}

\concern{Reviewer \#2, Concern \#6}

\concern{Reviewer comment:}

\rvcomment{Statistical independence assumptions. McNemar's test and Cochran's Q assume the 300 legitimate cases are exchangeable/independent units. Since cases are synthetically generated from a shared typology structure, some correlation across cases seems plausible. The authors use cluster bootstrapping over the eight typology strata for the secondary uncertainty estimates but not, as far as I can tell, for the primary McNemar/Cochran tests. Given how strong the effect is ($P = 2\times10^{-27}$), this is unlikely to change the qualitative conclusion, but a brief comment on why case-level inference is appropriate for the primary test would be useful.}

\textbf{Author response:}

\begin{itemize}

\item The reviewer has read the code correctly: the cluster bootstrap was applied to the secondary interval estimates only. Rather than defend case-level inference we extended the cluster-robust treatment to the primary test, where a permutation that applies a single permutation of model labels to all cases within each of the eight case-template strata gives Monte Carlo $p \approx 0.0005$ (plus-one correction) under either rule.

\item Adjacent-tier contrasts under the restored rule are 29.3 pp (95\% CI 12.6--51.2), 48.7 pp (25.8--72.5) and 41.7 pp (19.7--65.2). All exclude zero, and all are materially wider than case-level inference would give, so we report the wider ones.

\item On the $p$-value the reviewer quotes, the revision audit found two errors in our statistics. First, \texttt{stats\_tests.json} recorded it as 0.0 because the code computed one minus the chi-squared CDF, which underflows. Second, the $Q$ statistic itself was understated fivefold, because the code omitted the factor $k$ from the numerator. Under the preregistered rule the corrected statistic is $Q = 585.0$, $p = 2.7\times10^{-125}$; the submitted $Q = 131.6$ should have been $657.8$. The permutation result is unchanged, because a constant factor does not alter permutation ranks. The omitted factor understated Cochran's $Q$, while numerical underflow caused the archived $p$-value to be represented as zero rather than as a finite probability. Both errors have been corrected; neither changes the qualitative conclusion.

\end{itemize}

\textbf{Author action:}

\begin{itemize}

\item Section 2.4 now states the independence assumption, notes that cases sharing a case template are not independent, and reports the cluster-level permutation test as the primary inference.

\item Adjacent-tier contrasts are reported with cluster-robust bootstrap intervals over the eight strata.

\item The analysis code was corrected to use the chi-squared survival function. The capsule was re-run and re-hashed.

\item The Cochran's $Q$ implementation was corrected, all $Q$ values were recomputed from the frozen decisions and cross-checked against an independent implementation, and Section 2.4 records the correction.

\end{itemize}

\concern{Reviewer comment:}

\rvcomment{This manuscript investigates whether foundation-model choice materially changes the operating point of LLM-based anti-money-laundering transaction screening when the task and transaction cases are held constant. The topic is timely and the controlled cross-model design, paired statistical testing, reproducibility framework, and translation of false-positive rates into operational alert burden are valuable strengths. However, several methodological issues should be addressed before the conclusions can be fully supported, particularly the per-case aggregation procedure used to combine replicate model decisions.}

\rvcomment{Major comment --- label-dependent aggregation rule:}

\rvcomment{The preregistered aggregation rule resolves 2--2 replicate splits differently depending on the known ground-truth label: a tie on a legitimate case is treated as legitimate, whereas a tie on a suspicious case is treated as detected. Although this rule was preregistered and transparently disclosed, it uses information that would not be available in deployment and therefore may produce an optimistically biased evaluation operating point. This is especially important because ties affected a non-trivial number of model--case decisions. I recommend reporting the primary results under a label-independent aggregation rule and providing sensitivity analyses under alternative tie policies, such as treating ties as abstentions, always escalating ties, or analysing each prompt configuration separately. The authors should also clarify whether the headline false-positive and miss rates represent deployable model configurations or an evaluation-only aggregation procedure.}

\textbf{Author response:}

\begin{itemize}

\item We thank Reviewer 3 for identifying the aggregation procedure as the issue on which the conclusions depend. We agree and have made it the central revision.

\item The report states that several methodological issues should be addressed but sets out one major comment, which we answer in full below. We would welcome the opportunity to address any further comments intended to accompany this report.

\item We accept the criticism. The rule used the ground-truth label to choose the tie direction, both directions favoured the model, and that is an evaluation artifact rather than a property of any deployable screener. It is also not the preregistered rule: decision~D4 and both preregistration documents specify ties broken toward \texttt{flag} with no reference to the case label, so the benign branch as implemented was an undisclosed deviation, and we report it as such. We have restored the preregistered rule as primary, which is also the conservative choice on the false-positive axis and corresponds to routing a split panel to a human reviewer.

\item We ran each of the three sensitivity analyses named. Ties as abstentions give a spread of 84.9 pp on each model's retained cases, with Cochran's $Q$ computed on the 189 cases all five models decided; recomputed on those 189 cases the spread is 81.5 pp (Appendix~A), always escalating gives 83.3 pp, each prompt configuration separately gives 85.3, 85.0, 80.3 and 81.3 pp, and unanimity gives 77.7 pp. No pair of models reverses order.

\item On the final question: the four-call aggregate is an evaluation-only construct, since no institution would issue four calls per transaction and take a majority. The deployable quantity is a single call, where the false-positive rate runs from 0.3 to 2.3 percent for Gemini Flash and from 80.7 to 87.7 percent for GPT-4o-mini. The deviation understated every false-positive rate and left miss rates unchanged. A label-independent strict-majority rule reproduces the submitted false-positive rates but raises miss rates from 12.0, 3.3, 3.7, 0.7 and 0.0 percent to 18.3, 8.3, 7.0, 2.0 and 0.0 percent.

\end{itemize}

\textbf{Author action:}

\begin{itemize}

\item Section 2.3 states decision~D4 as preregistered and makes it primary.

\item Section 2.3 records the departure in the benign branch and every number it affected.

\item The Appendix~A sentence attributing a label-dependent rule to preregistration was corrected.

\item New Table 1 reports false-positive rates, the spread and Cochran's $Q$ under five aggregation rules and four single-call configurations.

\item Section 2.3 and Appendix~A state that the aggregate is an evaluation-only construct; Table 1 reports the single-call configurations as the deployable operating points.

\item Table 1 retains the deviating rule alongside the preregistered rule.

\end{itemize}
